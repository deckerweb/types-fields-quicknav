# Daten und Datenschutz

Das Plugin speichert dtfq_settings je Website: Provider- und Funktionsschalter, Frontend-/Inhaltsschalter, ausgeschlossene Inhaltstypen, Löschpräferenz und Schemaversion. Deaktivierung erhält die Einstellungen. Keine eigenen Tabellen, REST-Endpunkte, Cronaufgaben oder Telemetrie. Die eingebettete Library speichert gemeinsame Einstellungen, Installationszuordnungen, persönliche Ansichten und Caches unter eigenen Schlüsseln. Ihr optionaler Onlinekatalog ist anfangs aus; bei Aktivierung wird der konfigurierte GitHub-Katalog abgerufen. Installations- und Updateaktionen kontaktieren die jeweilige Paketquelle. Die Toolbar-Navigation selbst erzeugt keine externen Anfragen. Der mitgelieferte Updater prüft veröffentlichte GitHub-Releases im WordPress-Updateablauf; GitHub erhält dabei übliche Anfragedaten wie die anfragende IP-Adresse. Automatische Updates werden dadurch nicht eingeschaltet. Release-Entwürfe werden nicht als Updates angeboten. Rollensperren speichern Rollenschlüssel, Benutzersperren speichern Benutzer-IDs je Website. Sie verändern keine WordPress-Rollen oder Provider-Berechtigungen.

Unter Werkzeuge → Website-Zustand → Bericht zeigt Types & Fields QuickNav eine kompakte Zusammenfassung: Version, erkannte Provider, eingeschaltete Provider und Add-ons, Frontend-Navigation, Inhaltslisten sowie eingerichtete Rollen- und Benutzersperren als Ja/Nein. Keine Rollennamen, Benutzernamen oder Benutzer-IDs werden ausgegeben. Der Abschnitt erzeugt keine Gesundheitswarnungen und ist nur mit der WordPress-Berechtigung für den Website-Zustand zugänglich.
